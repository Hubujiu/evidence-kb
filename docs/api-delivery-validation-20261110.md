## 接口验证范围

HTTP 合同使用生产应用装配、真实临时存储、授权、解析、检索和会话，替换远端模型边界。覆盖上传、默认上下文拒绝、显式授权、条件更新冲突、发布前版本隔离、回答实际输入、引用原件读取、PARTIAL、重新解析、构建拒绝及解除绑定后的恢复。

请求恢复合同覆盖斜杠身份、按请求隔离事件、查询不改写状态、成功用量、缓存身份、响应后结算未知以及当前权限变化后的脱敏或拒绝。模型合同覆盖单次发送与结算、事实保留、生产者 guard 及可信 Provider 注册。交付恢复合同覆盖未知预留保留、认证读取、写入与发送拒绝、外部核查后仍须重启。

这些合成合同验证组件和接口行为，不是企业人工业务金标，也不表示生产 RAG 答案质量通过。统一评分器控制复用冻结 trace，重新执行当前确定性评分。没有新增远端模型、Embedding 或 judge 调用。

## 保留的失败与修复

ordinary-01 保留首轮失败：严格响应夹具使用错误的时间类型、历史合同身份改名、候选修订后的旧发布预期，以及离线 worker 不能启动 HTML 解析子进程。该轮另有一个分片超时，原因没有得到确认。后续检查串行执行，未修改超时门槛。

ordinary-02 的基础与宿主集成通过，全部离线分片结束，但保留两项 FAIL。API v6 输入清单补齐新恢复模型登记，并保持 v1 至 v5 不变。字段丢失负控通过 AST 删除 known_zero_send，继续要求函数摘要不变且模块绑定报告漂移。修复后 22 个相关合同通过，ordinary-03 完整通过。没有删除失败用例、降低门槛或忽略退出码。
