# 控制台构建与发布操作归属

基线：`f0ea7450b33b21022fbb61e91c1539d5a290c89b`。

## 问题与行为

诊断文档控制台允许不同按钮并行执行。构建 A 的响应与新建 B 后的列表响应在同一任务中完成时，内部 `json()` 检查之后、外层回调执行之前，列表回调可以把当前知识库改为 B。原发布回调随后仍向 A 发送发布请求，或把 A 的发布成功信息写到 B 的视图中。

本修复让一次“构建并发布”使用同一个原始范围标记，在第二次 POST 前及最终状态写入前分别核对。失效操作不继续发送，晚到的成功和失败不覆盖当前范围的消息。已发送的服务器操作可能已生效，前端抑制消息不代表回滚。

沿用现有 `currentScope/current/ownedFailure`，没有引入另一个生命周期框架，也没有改变上传、检索、引用、构建或发布后端接口。
