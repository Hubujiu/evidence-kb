## 所有权与接口边界

知识库权威存储拥有来源、不可变版本、解析、绑定、权限与发布清单。文档接口从这些记录计算视图，不保存新的就绪状态。更新现有来源须显式指定来源身份，条件更新使用现有 authority revision 防止丢失并发修改。撤权继续即时生效。

SessionStore 拥有逻辑请求、指纹、会话修订与完成结果。请求查询经应用入口并执行当前权限复核，不新增任务账本、不自动续跑或重发。提供者账本继续拥有物理请求身份、预留和结算；观察到的响应事实与结算确认分别表示。

公共 HTTP 错误只投影白名单字段。插件合同仍约束实际运行时响应，HTTP 声明复用公共合同。Provider 只能通过可信装配注册，配置不能导入任意代码。

## 验收界限

新增必要合同统一放在 kb_platform/rag_testing/*_contracts.py，实际调用 HTTP 路由和公共插件接口，使用真实临时数据库、检索与授权。合成原文和模型替身明确标注。RAG 证据评分复用统一 runner/scorer，与组件及权限合同分别报告。

现有通过记录 /opt/evidence-runs/integrated-20261110/ordinary-06 和 formal-02 仅作改造前基线，不作为本轮通过证据。本轮输出使用新的目录，旧记录只读。不存在本轮付费请求，因此新增远端调用上限为零。

本轮不改变 Rust 生命周期所有权，不增加通用任务服务。设计沿用已讨论并在代码中存在的来源、会话和物理账本结构，无需重新设计生命周期底座。

## 执行方式

先执行针对当前缺口的接口合同，保留失败基线；每批改动执行相关合同，再合并并运行完整门禁。模型与会话改动在独立 worktree 开发，由主工作区审查集成。状态机转换先审查模型、假设、排除与回归，再更新必要源码绑定。
