# 知识库授权数据协议

`knowledge.authority.storage/1` 是知识库数据插件和认证授权插件共享的公开数据合同。默认存储插件同时导出通用 `storage.service/1` 和这个专用出口；专用出口只访问配置中的 `repository.primary` 数据集。两个消费者通过 `requires.authority` 声明依赖，不再在通用存储接口中约定隐藏的表结构或绑定名称。

`describe({})` 返回数据集身份、允许的方法以及完整的关系表描述。`relational(request)` 使用公共 `storage_structured_wire` JSON AST 协议，包括 schema 准备、带作用域事务、语句、提交、回滚和提交结果未知。它不接受 SQL 字符串，也不允许调用方更换数据集绑定。数据集身份包含 application、owner、space 和 dataset ID；运行时 schema 的 owner 来自该身份。

纯函数 `authority_schema_descriptor()` 提供中立表描述，包含版本、列类型、约束、作用域、索引和只追加表。机器可读合同位于 `config/contracts/knowledge-v1.json`，其中不写入部署身份。`describe` 额外携带实际 owner 和 schema digest。客户端核对 owner 与中立结构后，在 prepare 中使用提供者声明的不透明 digest；不要求其他语言复现 Python 的内部哈希算法。

使用内置知识库数据和授权实现时，应用配置必须把两者的 `authority` 绑定到同一个插件实例的同一个出口。绑定不一致在任何插件挂载前拒绝；不能把两份各自合法的数据集当作同一授权状态。替换存储提供商时，新的出口仍须满足本协议、schema 和事务语义。

替换知识库数据实现必须遵守下列写入语义：

- 所有记录和查询按租户隔离，涉及知识库的表同时绑定知识库作用域；成员能力和来源拥有者、读者决定访问权限。
- 成员、来源策略、来源读者、活动来源绑定和发布状态的变化，必须在同一事务中维护知识库修订和租户授权修订。调用方锁定并比较授权修订后才能处理模型请求或发布构建。
- 来源原文版本、解析快照和引用记录只追加，保持原文哈希、来源版本、解析身份及引用内容不可变。更换来源使用新的版本和活动绑定，不修改已发布引用指向的内容。
- 构建保存预期发布版本、授权修订、知识库修订及准确的来源输入。文档 Embedding 只处理仍为 STAGING 且输入未变化的构建；查询只使用当前已发布构建及当前允许的来源与提供商。
- 发布必须原子更新构建状态和知识库 manifest 指针。授权服务读到的来源身份、文本哈希和处理策略须与数据插件使用的记录一致。
- 提交结果未知保留 operation ID，不能当作回滚或成功，也不能通过盲目重放业务写入消除未知状态。

这些规则属于公开协议，而不是 SQLite 或 Python 实现细节。其他语言可以依据机器描述和 JSON AST 实现相同出口；使用其他物理数据库时仍须保持相同的身份、约束、隔离与事务效果。需要改变这些语义或表定义时发布新的协议主版本。
