## 范围与完成条件

保留 Rust 主宿主和多语言插件改造。修复 `dev-workflow` 的重复动作停止与完成状态冲突，以及 `dev-enumeration` 的模型输出合同失败。增加确定性回归和 CI 集成覆盖，评估 tester-army/e2e 并提交可审查 PR。

完成条件是旧行为有失败证据，当前统一检查通过，两个缺陷有行为回归，真实调用的增量结果保留独立报告，PR 已创建。外部模型仍可能返回非法文本，必须在边界拒绝，不能承诺消除模型的全部随机失败。

先并行只读定位两条故障链，再比较至少两种结构方案。实现期间各工作流独占文件，完成一个边界后运行对应回归。全量检查和独立审查放在最终提交之前。

既有付费记录保持只读。首先复用已保存请求建立离线复现。只有离线证据不足时，按现有授权和账本剩余额度执行有限增量调用。CI 默认不使用模型密钥。

吞吐检查点是完成两个根因定位后重新评估任务分割。源代码修改、CI 和发布各自使用独立提交，避免等待付费模型期间重复执行检查。

## 设计选择

上下文继续用半开原文区间 `(start, end)` 表示选取内容。完整区间能通过现有序列化预算检查时优先发送完整原文。超出预算才选择段落。完整性从区间端点导出，不增加另一份可漂移的布尔状态。候选方案是修改段落分割使其覆盖空白，但它会影响检索展开和标题证据，不采用。

规划、答案和核验各自拥有输出协议。答案的引用指令不能进入规划调用。每次逻辑模型调用最多进行一次格式纠正，整个 turn 的物理调用总限额、截止时间和答案预留保持原有约束。候选方案是要求提供商原生约束解码，但当前适配器没有验证该能力，不能把协议兼容性当作已知事实。

这些方案通过根因匹配、边界影响、预算安全、接口大小和可复现性比较。选取各自最小方案，不拼接额外抽象。没有可用的技能默认跨模型裁判，本轮由主代理核对原始源码与两份独立调查。旧的 repeated_action 降级规则保留，严格 JSON 和 Schema 拒绝规则也保留。
