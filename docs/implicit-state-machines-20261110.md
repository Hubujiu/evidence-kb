### React 恢复的两个必要边界

`model_sent=False` 只表示模型发送事实；它不能单独解除 `COMMIT_UNKNOWN` 或 `inspect_operation` 对整轮事务的未决状态。`interrupted` 也可能永久存在，不能因此永久锁住所有未来聊天。实现已保留原 request/session/attempt，明确呈现未决状态，并提供显式保留旧记录、开始独立空白会话的动作；不静默重发旧问题，也不通过删除记录消除未知。

### 已取得证据的准确含义

ProcessTransport 的两个新增合同在旧实现均失败，修复后 process/host/combination 45 个定向合同通过；直接有限正模型得到 7 个不同状态，两个负控准确违反各自的不变量。Console 的真实模块 Node 合同在旧实现有两个竞态失败，修复后 11/11 通过，独立 Python 组合/浏览器源码合同 34/34 通过；直接正模型为 64 个不同状态。Embedding 使用真实本地 SQLite/EmbeddedSearch 和公开插件链路、固定合成向量复现；Rerank 使用公开 EvidenceClient 的受控双失败复现。这些结果分别证明具体组件行为，不代表真实线上频率、付费请求损失、整个浏览器或全部合并分支正确。

当前环境的完整普通和 formal-only 必需入口均曾实际运行并失败于受控子进程所有权发现能力缺失，`OWNED_CHILD_DISCOVERY_UNAVAILABLE` 对应 `/proc/self/task/<pid>/children` 无法读取；浏览器另受 socket `EPERM` 限制。这些失败保持为失败，未改门禁。上述本地失败与远端 CI 是独立证据：PR87–90 的当前 head 已在支持所需能力的 CI 中通过完整门禁；PR91 等待其独立运行。

## 3. UX、DX、AX 的共同决策

| 决策 | UX | DX | AX |
| --- | --- | --- | --- |
| 保留每个边界的唯一状态所有者 | 同一操作显示一致结果和可执行动作。 | 继续复用 Rust coordinator、SessionStore、BudgetLedger、OperationOwner；不增加平行 enum、持久 ready 布尔或新全局 FSM 库。 | 代理只根据权威身份、revision、receipt 和允许动作推进，减少凭 UI 字符串推断。 |
| 把执行、观察、提交、交付与清理分别表达 | 收到答案后刷新失败只显示同步警告；已发送但未确认时给出明确恢复入口。 | 独立字段和类型表达确有独立所有者的事实，避免 success/failed/unknown 同时承担五种含义。 | 知道哪个事实已确定、哪个证据缺失，能查询原请求而不凭失败自动再发。 |
| 不可变内容身份和当前授权同时校验 | 候选更新不使旧发布版本突然不可搜索；撤权仍立即影响后续准入。 | 调用者显式选择 candidate/published，复用已有快照与 postflight。 | 每条证据可追踪到 source/version/manifest 与当前 authority revision。 |
| 歧义结果保留原请求身份，恢复默认只读 | 问题和已知答案得到保留；长期中断可保留旧记录并明确开始独立空白会话。 | 客户端消费既有 request_status 判别式；model_sent=False 只描述模型发送事实，不自动决定整轮事务已解决。 | 恢复路径不重复提交旧业务请求、不隐式付费重试，并保留原 request/session ID。 |
| 在真正的准入和提交边界设置守卫 | 切换知识库后旧操作不继续发布、不写当前状态；关闭后的对象不会再启动进程。 | 沿用现有生命周期锁和 scope stamp，以最小局部改动修复经复现的竞态。 | 守卫提供确定错误码与稳定终态，便于工具判断是否可继续。 |
| 主错误与清理错误同时可观察 | 保留真正失败原因及其恢复指引。 | 原异常对象及 code/call_record/usage 保留，cleanup failure 附加诊断；不谎报 continuation 已清理。 | 物理请求身份和未知费用仍能用于后续调和。 |
| 从服务端投影就绪原因和允许动作 | 区分已连接、可读、可搜索、可问答、候选阻塞和恢复只读。 | 使用 documents/readiness/budget 字段，避免多个页面重新发明 readiness。 | 结构化 blockers、recovery_action 和 nullable unknown 数值比单个 available 更可行动。 |
| 把证据层级和有限模型边界写清楚 | 不把合成测试或模型通过包装成线上质量保证。 | 每个模型保留假设、bounds、exclusions、named negatives 和源码映射；哈希只检查漂移。 | 自动审查能区分 source_review、reproduced、targeted_pass、full_gate_fail 和 pending_ci。 |
| 独立修复后再做组合清单和联合验收 | 每项小改动可单独回退和评估兼容性。 | 各分支保留冻结 v1–v6，合并时对所有 v7 增量取并集并保留全部合同，不选择一份覆盖另一份。 | 修复状态、基线与联合验证范围可机读，避免把多个分支的 PASS 相加当一个产品通过。 |

## 7. 组合与实施顺序

第一步是逐项审查和通过独立修复。第二步是对共同修改的 registry、browser source review 和 active combination manifest 做明确合并。独立 `*-v7.json` 不是可互相覆盖的替代品；合并后的清单须保留所有旧义务及各分支新增模型、负控、源码 binding 和合同身份。第三步对精确合并提交运行两个必需入口及对应浏览器/真实集成。只有该 tree 的实际结果能成为联合验收。

既有三条 composition edge 分别连接工具重试/熔断/回执/预算、应用存储/提供商清理、授权撤销/会话提交。它们提供有界组合检查，不能自动扩展到全部切片。JSON 原样保留这些 edge，以便代理按实际 source/contract/model 继续审查。

后续改动继续使用本项目统一合同和 checker，不增加临时付费评测体系；先用精确已有证据和确定性回放，仅在缺失的实际风险边界补合同。改变转换前先审模型、假设和 exclusions，再更新源码摘要。

## 8. 证据与非结论

本文仅新增文档和机读清单；没有修改活动源码、测试或模型注册表。新增远端模型、Embedding 和 judge 调用均为 0。审计不声称生产发生率、线上延迟、答案质量或成本改善百分比，也不保证操作系统、数据库、网络、第三方插件及任意规模输入正确。

直接源码审阅、受控组件复现、定向合同、有限模型、真实浏览器/数据库集成和当前 head CI 是独立证据层。源码 hash 证明审阅绑定未漂移，不证明模型覆盖所有代码。当前保留的未确认状态和失败结果，是可继续工作的事实。
