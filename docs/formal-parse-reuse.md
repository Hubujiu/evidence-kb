# Invocation-local formal source parsing

The registry still resolves and confines each source path, verifies that it is a file, and reads fresh UTF-8 text for every binding. Only Python parsing and symbol discovery for identical complete source text are reused inside one registry invocation. The scoped cache holds at most 128 entries and clears in `finally`, including on failure. It never uses path, timestamp, size, or a caller-supplied hash as authority.

This follows the standard-library [functools caching guidance](https://docs.python.org/3/library/functools.html#functools.lru_cache): memoize deterministic computation with hashable inputs, not side effects or public mutable results. Cached ASTs remain private to the digest callback. Callers receive only the existing digest string; public `python_symbols` continues returning independent mutable trees, and public `source_digest` remains uncached. Syntax failures are not cached. The existing Python-version-aware AST dump remains unchanged.

No filesystem snapshot is asserted. A content change between two reads uses a different parse key. Path resolution and confinement still occur before every read, so this change neither adds nor removes the existing filesystem TOCTOU boundary. Symlink replacement, missing files, and permission failures must still be checked on subsequent calls.

The mandatory source-quality lint fixes these narrow cache ownership and fresh-read boundaries. Contracts cover unchanged I/O call counts, repeated symbols, same-size/mtime changes, distinct roots, symlink escape, exceptions, cleanup, independent public ASTs, and exact cached/uncached violation-list equality. Existing semantic mutation and refreshed-source-hash contracts remain mandatory.

This change does not modify model inventories, negative controls, worker sharding, deadlines, or assertions. Linux profiles established redundant parsing, not a Windows speed guarantee. The original PR74 Windows 170-second timeout remains a recorded failure until a new exact-commit Windows run passes. Passing finite model checks does not prove the absence of all implementation bugs.

## Named declaration traversal

The second optimization follows the official [CPython abstract grammar](https://docs.python.org/3.12/library/ast.html#abstract-grammar): named function and class definitions are statements, not descendants of expressions. While discovering those names, `python_symbols` does not recurse into `ast.expr` subtrees. Parsing still creates the complete AST, and the ASTs returned for each name are unchanged, including expressions, locations, and nested bodies. Digest computation and state discovery continue inspecting their original complete trees.

The traversal retains statement containers such as conditional/loop bodies, exception handlers, exception groups, match cases, and asynchronous constructs. It accepts actual source through `ast.parse`, not caller-supplied ASTs. Full-repository differential checks on Python 3.12 and 3.13 compared ordered symbol keys and every full AST dump across 510 tracked Python files. A permanent grammar-container fixture and a seeded incorrect statement-pruning mutation constrain this optimization. This does not change worker allocation or promise every platform's deadline will pass.

Candidate discovery uses the same ASDL boundary after inspecting the current assignment targets: expression children cannot contain Assign, AnnAssign, or AugAssign statements. The full AST remains available to all other checks. Existing tuple-target and NamedExpr exclusions are deliberately unchanged. Contracts compare the original unpruned candidate scan through every statement container and direct, chained, attribute, and subscript targets.

After a failed Windows quality gate, CI runs one read-only registry cProfile diagnostic with a separate three-minute bound, then uploads the ordinary evidence. It neither reruns contracts nor replaces or suppresses their result. The diagnostic records the exact checked-out Git head/tree, Python version, logical CPU count, wall/process CPU time, ordered sanitized violations, and sanitized per-function statistics. Repository paths are relative and external paths are reduced to basenames. It does not record environment values, call arguments, caller details, source text, or raw profile dumps. Mandatory workflow lint prevents conditional or optional ordinary checks, broadened diagnostics, relaxed diagnostic bounds, or moving the diagnostic past evidence upload. An absent diagnostic after runner interruption remains missing evidence, never a pass.

Candidate discovery additionally caches only the pure source-text-to-frozenset-of-symbols result. Current STATE_NAMES is an explicit immutable cache key input. The standard-library LRU retains at most 512 entries, admitting an entry only when recursive sys.getsizeof of its source, state-name set and result is at most 256 KiB; retained payload is therefore bounded by 128 MiB plus bounded LRU bookkeeping. Oversized results are returned without admission; parse errors are not cached. No path, root, permissions or AST is stored. Every invocation still enumerates roots and files, resolves confinement, reads current content, and combines symbols with the current relative path. The separate existing invocation-local digest parser cache is unchanged.

The tempting combined all-symbol digest cache was rejected: a legal source file with a deep expression can be discovered and its small bound method hashed successfully, while eagerly dumping its unrequested module AST raises RecursionError. A permanent negative control retains this distinction. Candidate caching does not compute any unrequested digest.
